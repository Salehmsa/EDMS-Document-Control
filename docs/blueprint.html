§ 01

Position & the one decision that mattersنقطة البداية والقرار الجوهري

القائمة الحالية Official Documents على SharePoint ليست نقطة صفر — بل أساس صالح. المطلوب ليس بناء نظام جديد من العدم، بل تحويل سجل يدوي إلى نظام حوكمة آلي بطبقات تنبيه وموافقات وتدقيق وامتثال، دون شراء منصة جديدة ودون صلاحيات إدارية على أجهزة المستخدمين.

The existing Official Documents list already carries the right column set — document number, issuing authority, company, issue and expiry dates, department owner, reminder date, mandatory flag, days-to-expire, status. That is not a starting point to discard. It is a register that has outgrown being a register.

What it lacks is everything that turns a list into a control system: a status value that is actually true today, an alert ladder that escalates, an approval chain that is evidence, an audit trail that survives a deletion, and a retention policy that a regulator would accept. This specification adds those seven layers on top of what exists, on the Microsoft 365 licences the organisation already owns.

The decision this document argues for

Build on SharePoint Online, not Dataverse — for now. Dataverse gives a proper relational model and row-level security, but it requires Power Apps Premium at $20/user/month. At 200 users that is $48,000 a year before a single line of logic is written. SharePoint Lists handle thousands of documents comfortably when the views are indexed and filtered. The migration trigger to Dataverse is written into §11 so the decision is revisited on evidence, not on a hunch.

§ 02

System architectureالبنية التقنية للنظام

Five layers, with governance running vertically through all of them. The notable feature is the premium lane: every flow that needs an outbound HTTP call is isolated behind one service account, so premium licensing is a single $150/month line rather than a per-user tax.

§ 03

Data modelنموذج البيانات

القاعدة الحاكمة: البيانات الوصفية مفصولة عن الملفات. الجميع يرى أن «السجل التجاري» موجود وتاريخ انتهائه — لكن فتح ملف PDF للضمان البنكي محكوم بصلاحية مستقلة. هذا الفصل هو ما يجعل النظام قابلاً للتوسع أمنياً.

Metadata and binaries are separated on purpose. The registry list holds the facts everyone needs to see; the document library holds the files, with its own permission surface. That is what lets "every employee can see the company holds a valid CR" coexist with "only Legal can open the bank guarantee PDF" — without duplicating rows or breaking inheritance on thousands of items.

Access controlصلاحيات الوصول والأدوار

Permission architecture — the scaling trap

Do not apply unique item-level permissions per document. SharePoint supports 50,000 unique permissions per list but degrades badly past 5,000, and every break-inheritance operation is a write. Instead: the registry list stays readable to all staff (metadata is not the secret — the PDF is), and the document library is partitioned into folders by department with Entra security groups mapped to SharePoint groups. Confidential and Restricted files live in a separate library with its own inheritance break. Permission count then scales with the number of departments, not the number of documents.

§ 06

The notification ladderسُلّم التنبيهات المتدرج

التنبيه الواحد قبل الانتهاء لا يكفي. النظام يعتمد سُلّماً متدرجاً يتصاعد في الجمهور والقناة معاً — يبدأ بالمالك، وينتهي عند الرعاية التنفيذية ورسالة نصية.

Frequency escalates, but so does audience and channel. A reminder that goes to the same person through the same channel five times is one reminder repeated; a reminder whose recipient list widens is an escalation.

§ 07

Security & complianceالأمن والامتثال التنظيمي

الامتثال الأهم لشركة سعودية ليس GDPR بل نظام حماية البيانات الشخصية السعودي (PDPL) الصادر عن سدايا — وهو نافذ ومُطبّق فعلياً، بغرامات تصل إلى 5 ملايين ريال قابلة للمضاعفة عند التكرار.

Regulatory frame — Saudi first

The organisation is a Saudi entity. The binding regime is the Personal Data Protection Law (PDPL), enforced by SDAIA. It became fully enforceable on 14 September 2024 and is now in an active enforcement phase, with penalties up to SAR 5 million, doubled for repeat violations. GDPR applies only where EU personal data is in scope — treat it as secondary, not primary.

Control stack

Data protection

  • In transit: TLS 1.2+ enforced tenant-wide; legacy protocols disabled
  • At rest: BitLocker volume + per-file AES-256, Microsoft-managed keys. Customer Key via Azure Key Vault only if Legal requires key custody
  • Sensitivity labels: Public / Internal / Confidential / Restricted, inherited from the document type. Confidential and above get encryption + watermark
  • DLP: block external sharing of Confidential+; policy tips shown at the point of action, not after
  • Conditional Access: MFA always; block download on unmanaged devices for Restricted

Resilience

  • RPO ≤ 1 hour, RTO ≤ 4 hours — both rehearsed, not assumed
  • Native recycle bin gives 93 days and is not a backup. A dedicated backup product is a line item, not an optional extra
  • Restore drills quarterly: single item, single file version, full site
  • A failed backup job raises an alert within one hour — an unmonitored backup is a belief, not a control
  • Ransomware path tested via Defender detection + restore drill
§ 08

Seven defects that kill SharePoint document trackersسبعة أعطال تُفشل أنظمة تتبّع الوثائق

Every one of these has been the root cause of a real expiry going unnoticed. They are listed here because the design decisions in §2–§6 exist specifically to prevent them, and a reviewer should be able to check each one off.

01The frozen Today()

A calculated column = ExpiryDate − Today() evaluates only when the item is written. The value silently freezes and drifts further from reality every day. Nothing errors; the column just quietly lies.

Prevented by Flow 01 stamps DaysToExpire nightly. Power BI recomputes independently and raises an alarm on any disagreement (§9 Flow Health).

02Duplicate alert storms

Recurrence flows double-fire on service retries and manual re-runs. Two hundred people get the same alert twice, learn the system cries wolf, and create a mailbox rule. The system is then dead while still appearing to work.

Prevented by NotificationLog.IdempotencyKey = item + tier + date, checked before every send.

03Silent flow death

A flow gets disabled by a licence lapse, an owner leaving, or a connection expiring. No alert fires because the thing that fires alerts is the thing that died. Discovery is typically weeks later, via a lapsed licence.

Prevented by Flow 09 watchdog: escalates if no run summary in 26 hours. Plus the Flow Health measure on the dashboard.

04Version history explosion

A nightly job that writes every row generates 5,000 versions a day — 1.8 million a year. It destroys Modified By as a signal, bloats storage, and eventually hits the 50,000-versions-per-item ceiling.

Prevented by Flow 01 writes only when a value actually changed. Correctness requirement, not an optimisation.

05The 5,000-item view threshold

A list happily holds 30 million items, but any view that filters or sorts on an unindexed column fails past 5,000. It works perfectly in testing with 200 rows and breaks in production two years later.

Prevented by Nine indexed columns; every shipped view filters and sorts on one. Verified at 6,000 items in tests A07–A08.

06Recycle bin as backup

93 days of recycle bin plus Microsoft's own short retention is not a backup policy. It does not survive a deliberate purge, a rogue script, or a discovery made in month four.

Prevented by A dedicated backup product with rehearsed RPO/RTO. Test H02 exists specifically to prove native retention is insufficient.

07Item-level permission sprawl

Breaking inheritance per document feels like precision. Past ~5,000 unique permissions, list rendering, search indexing, and every permission write slow to a crawl, and nobody can answer "who can see this?".

Prevented by Metadata open, files partitioned by department folder and security group. Permission count scales with departments, not documents.

The meta-defect

All seven share a shape: the system continues to look healthy while it has stopped working. A green dashboard fed by stale data is worse than no dashboard, because it actively prevents the question from being asked. That is why Flow Health is on the dashboard next to the compliance score, and why the watchdog is flow 09 rather than a nice-to-have.

Dataverse migration trigger

Move off SharePoint Lists when any two of these become true: registry exceeds 100,000 items; more than 50 concurrent editors at peak; a genuine need for row-level security on metadata rather than files; or more than three additional entities with real referential integrity requirements. Until then, Dataverse is $48,000 a year of capability that would go unused.

Decisions needed before week 1

  1. Tenant data region — KSA or elsewhere. Determines whether PDPL cross-border machinery applies to the whole system.
  2. Backup product — Microsoft 365 Backup, or a third party (Veeam, AvePoint). Affects the cost model and the RTO commitment.
  3. eSignature — SharePoint eSignature (in-tenant, cheaper, weaker external standing) or Adobe/DocuSign (premium, stronger for counterparties).
  4. Build model — internal, partner-led, or hybrid. Determines the calendar more than anything else in this document.
  5. Executive sponsor — the escalation ladder terminates somewhere. Who is at the top, by name.
